# 地図ポットン（旧称: 地図パック）設計メモ

2026-10-20 に表示名を「地図ポットン」に改名した（レベル名は 都道府県ポットン / 自治体ポットン / ご近所ポットン）。URL・DBのテーブル名・コード上の名前は「地図パック（map-pack）」のまま。以下の本文は改名前に書いたため「地図パック」と表記している。

ステータス: プロトタイプ実装済み（2026-10-19、3レベル＋ランキング）。ゲーム名・未決事項は末尾参照。

## コンセプト

箱の上から地域ピースを落として積む、スイカゲーム型の落下パズル。**地理的に隣接するピース同士が触れると、実際の地図上の位置関係のまま1つに固まる**。固まるほど箱に余裕ができ、最後は地図が1枚に完成する。

参考にしたゲーム: 「新・都道府県ゲーム」(https://sns.dopagamelab.com/pref-pack/)。ブラウザ版の公開HTMLを読んで仕組みを把握したが、ゲーム本体のコードにはライセンス表記がないため**コードは流用せず、仕組みだけを参考にして自前で実装する**。同ゲームが使っている Matter.js（物理エンジン）と poly-decomp（凹多角形の凸分解）は MIT ライセンスなので、こちらも同じものを使ってよい。

### 参考ゲームから取り入れる仕組み

- **合体＝再構築**: 触れた2ピースを消し、構成する地域の元の座標から1つの複合ボディとして作り直す（ピースの回転角は引き継ぐ）
- **合体で縮む**: ピースの画面上の大きさを「実面積^0.7」に比例させる（一辺は面積^0.35）。この式だと合体後の面積が元の合計より小さくなるため、**合体するほど箱に隙間ができる**。スイカゲームの「合体すると消えて空く」にあたる仕組み
- **隣接判定はパーツ単位**: 物理エンジンが報告する接触は凸パーツ単位なので、実際に触れている地域同士が隣接しているかで判定する（合体済みピースのどこかが触れただけで合体、にはしない）
- **出題の偏り**: 一定確率（参考ゲームは60%）で、箱の中にある地域に隣接する地域を優先して落とす。完全ランダムだと合体相手がおらず詰みやすい
- **全ピースが1つに固まったらクリア**

### 参考ゲームと変えたところ（2026-10-19 決定）

- **あふれても終了しない**。壁を上方向に十分高くしておき、積み上がっても遊び続けられる。ゲームの目的は「失敗しないこと」ではなく「地図を完成させること」
- **揺らすボタンは入れない**（参考ゲームそのままになるため）。代わりに次の2つで詰まりをほぐす
  - **ピースが跳ねる**: 止まっているピースは大きさを問わず時々ポンと跳ねて回る（小さいほど高く・頻繁に）。小さいピースは反発係数も高い
  - **積み直すボタン**: 箱の中のピースを全部取り出し、ランダムな順番・向きで1つずつ（150msおき）落とし直す。落とす位置は7割の確率で、箱の中にある隣接町丁の真上に寄せる。1回50点減点（0点未満にはしない）。落とし直しが終わるまでは再度押せない
    - 経緯: 最初は「シャッフル」の名前で「全ピースを同時に跳ね上げる」→「まとめて上に積んで同時に降らせる」を試したが、どちらも同じ速さでまとまって落ちるため並びが変わらず、試遊で「全く動かない」「結局ダメ」と言われた
    - Node上のシミュレーション（戸塚区の実データ、落とす順番・位置はランダム）では、全53ピースを落とした時点で36〜43ピース残り、積み直し1回ごとに残りが概ね3〜4割減った（4回で6〜8ピース）。最後の数ピースまで減らすのはまだ難しい
- **同じ町名のピースは連続して落とす**。最初から合体済みにはせず、たとえば戸塚町なら4ピースを続けて出し、「戸塚町（2/4）」のように何個目かを表示する。町名の選び方には参考ゲームと同じく、箱の中の町丁に隣接するものを優先する偏り（60%）を入れる

## 3レベル構成

地図パズル(`/game/map-puzzle`)と同じく 都道府県 / 市区町村 / 町丁 の3レベル。データは地図パズルと同じ CloudFront の geojson をそのまま使う。

| レベル | データ | エリア選択 | ピース数（実測） |
|---|---|---|---|
| 初級: 都道府県 | `/geojson/prefecture/prefectures.geojson` | なし（全国固定） | 47 |
| 中級: 市区町村 | `/geojson/municipality/2020/{pref}.geojson` | 都道府県を選ぶ | 19（鳥取）〜62（東京）〜188（北海道） |
| 上級: 町丁 | `/geojson/town-district/2020/{pref}/{city}.geojson` | 市区町村を選ぶ | 例: 大田区 220 |

エリア選択UIは地図パズルの `MapAreaSelector` を流用する。

### 開発・公開の順序（2026-10-19 決定）

**上級（町丁）から作って公開する**。都道府県レベルは参考ゲームとルール・見た目がほぼ同じになり、パクリと受け取られかねないため。町丁の境界データで遊べること自体がうさぽ独自の要素で、参考ゲームとの一番の違いになる。都道府県レベルは最後に回す（出さない選択肢もある）。

- 中核の仕組み（落とす・隣接で固まる・揺らす）は参考ゲームと共通なので、画面のどこかに着想元のクレジットを入れる
- 町丁は技術的に最も難しいレベル（ピース数・面積差・島や飛び地）なので、試作の段階から下記 1. のピース数上限を入れ、試作用エリアは町丁数がほどほどの市区町村に固定する

### 試作エリア: 横浜市戸塚区（14110）

実データ（`/geojson/town-district/2020/14/110.geojson`）を調べた結果、試作に向いている。

- **53ピース**: 参考ゲームの47ピースに近く、ピース数上限を入れなくても全ピース出題で成立しそう
- **MultiPolygonなし、穴ありは1件のみ**、外周の頂点は合計約9,100
- **全ピースが陸続きで1つにつながっている**（頂点共有で計算した隣接数は最小2・中央値5・最大13、孤立ピースなし）。離島・飛び地の問題が出ない
- **面積差は約140倍**（最小約1.7万㎡〜最大約240万㎡）。都道府県（約45倍）より大きいので、サイズ則の指数かクランプの調整が要る
- **同じ町名のピースが複数ある**: 下倉田町×3、戸塚町×4、深谷町×2、名瀬町×2、吉田町×2（統計上の小地域分割）。町名単位では45種類。最初から合体済みにする案もあったが、**連続して落とす**方式に決めた（上記「参考ゲームと変えたところ」参照）

## 技術的な論点

### 1. ピース数が桁違いになる問題（最重要）

参考ゲームは47ピースで調整されている。中級の北海道（188）や上級（数百）は、そのままでは次の問題が出る。

- 1プレイが長すぎる
- 箱の中のピース数が増えると物理演算が重くなる（スマホ想定）
- 小さすぎて見えない・つかめないピースが出る

対策の候補（未決、試作で確かめる）:
- **(A) 1プレイの上限ピース数を設ける**: たとえば50前後を上限とし、それを超えるエリアは「連続した一部の地域（隣接でつながったN個）」を出題範囲にする。完成するのはエリア全体ではなく、そのブロックになる
- **(B) 全ピース出題のまま、サイズ則と箱サイズで吸収する**: 合体で縮む効果が大きいので、全部入る可能性はある。ただし所要時間と負荷の問題は残る
- **(C) 中級の大きい県・上級の大きい市区町村は、小さく区切った単位を選ばせる**（北海道なら振興局単位など）。データの用意が必要

まずは (A) で試作するのが現実的。

### 2. 隣接関係の算出

参考ゲームは都道府県の隣接表を手書きしているが、3レベルに対応するため**geojsonの境界から計算する**。境界線を共有する（頂点・辺が許容誤差内で接する）ポリゴン同士を隣接とみなす。

- 町丁レベルは1市区町村分（数百ポリゴン）なのでクライアント側で計算できる
- 都道府県・北海道の市区町村は頂点数が多い（全国47都道府県で約16万頂点、北海道の市区町村で約25万頂点）。計算前に簡略化するか、事前計算した隣接表を静的JSONで持つ

### 3. 離島・飛び地

陸続きの隣接相手がいない地域（離島の自治体、沖縄県、島の町丁など）は誰とも合体できず、箱を占有し続けて詰みの原因になる。

- 都道府県レベル: 参考ゲームと同様、沖縄・鹿児島などは「海を挟んだ隣接」を手動で追加する
- 市区町村・町丁: 重心間距離などで最寄りの地域と仮想的に隣接させるか、出題から除外する。地図制覇ゲームのモックでも「陸続きでない自治体は連結成分から除外」という同種の判断をしている

### 4. 形状の簡略化と物理形状

- 描画用と物理演算用で別の精度を持つ。物理用は Douglas-Peucker で間引いてから poly-decomp で凸分解する
- MultiPolygon（飛び地を持つ地域。北海道の市区町村で15件、東京で14件）は複数のパーツをまとめた1つの複合ボディにする
- 穴（他地域を内包するポリゴン）は物理形状では無視し、外周だけを使う
- 合体後の大きなピースの中では個々の地域が小さく表示されるので、物理形状はさらに粗くてよい（参考ゲームも表示サイズに応じて精度を落としている）

### 5. ピースのサイズ則

一辺∝面積^0.35 は都道府県の面積差（香川〜北海道で約45倍）に合わせた値。市区町村・町丁は面積差がもっと大きい（町丁は数百倍以上もありうる）ので、指数や最小・最大サイズのクランプはレベルごとに調整が必要。

## スコア・ランキング

点数はゲームの主目的にしない。既存の地図パズルと同じ仕組み（挑戦履歴テーブル＋エリア別ベストテーブル＋DBトリガーでのスコア再計算、エリア別ランキング）に乗せる。

- スコアの元になる値の案: 固めたピース数・残りの箱の余裕・所要時間
- 物理演算はクライアント側で動くため、スコアの元になる値は自己申告になる。地図パズルも同じ前提（クライアントが送るピース数・ミス数・時間からDB側で計算）なので、それに合わせる
- 新しいテーブルを作る場合は、CLAUDE.md の教訓どおり**テーブル・関数とも `anon` への REVOKE を明示し、実機で権限を確認する**

## 実装（2026-10-19）

戸塚区固定の試作で手触りを確かめたあと（ユーザー評価「まあまあいい」）、地図パズルと同じ3レベル＋ランキングに広げた。

### 画面

- `/game/map-pack`: トップ（難易度選択・ランキングへの導線）。サイトのトップページにプロトタイプとして導線あり
- `/game/map-pack/[difficulty]`: プレイ画面。初級は全国固定、中級・上級は地図パズルの `MapAreaSelector` をそのまま使ってエリアを選ぶ
- `/game/map-pack/ranking`（難易度別）、`/game/map-pack/ranking/area?...`（エリア別）。結果画面から「このエリアのランキング」に飛べる

### 地図データの前処理（`src/lib/game/mapPack/regions.ts`）

- 地域名のプロパティ: 都道府県 `name` / 市区町村 `cityName` / 町丁 `S_NAME`
- **頂点の間引き**: 地域の一辺（√面積）の中央値×1%の誤差で間引く（北海道の市区町村は約25万頂点あるため）。最初は全体の大きさを基準にしたが、小笠原まで含む東京都で本土側を間引きすぎたため変更
- **遠い島の除去**: 地域の中で、最大のリングから「最大リングの一辺×3」より遠い島は捨てる（小笠原・先島諸島・奄美など）
- **隣接**: 頂点共有で判定。穴のリングの頂点も登録する（ほかの町丁に囲まれた飛び地が孤立しないように。小田原市で18ピースが孤立していた原因）
- **陸続きでない島(群)**: 最大のかたまりから一番近いかたまりを順に1本ずつつなぐ。本土側の大きさの4%より離れていれば、その距離まで本土側に寄せる（沖縄・伊豆諸島など。合体したピースが間延びしないように）
- 実データで確認した結果、都道府県・北海道/東京都/沖縄県の市区町村・小田原市/戸塚区の町丁のすべてで、全地域が1つにつながった

### ゲーム本体（`src/components/game/map-pack/MapPackGame.tsx`）

- Matter.js の物理演算と canvas 描画。合体時は大きい方のピースを動かさず、小さい方を地図上の正しい位置に吸い寄せる
- **ピースの大きさ**: 一辺 = 係数×面積^0.35。係数は「全ピースをばらばらに並べた面積の合計が箱の50%」になるように決める。合体ピース（完成形を含む）は直径が箱の幅の90%に収まるよう個別に縮める。最小の一辺は12。最初は「完成形が箱に収まる」大きさを基準にしたが、日本列島のように細長い地図だとピースが極端に小さくなった（中央値で一辺14、箱の9%）ため変更
- 物理形状の凸分解（`shapes.ts`）は、許容誤差を地域の一辺に比例する段階に分けてキャッシュする（都道府県と町丁で桁が違うため）
- 操作: 指（マウス）の横位置で狙い、離すと落ちる。「やり直す」「積み直す（-50点）」「あきらめる」ボタン
- 試遊の感想: ピースがプルプル動くのは面白い（物理演算の揺れは残す方向）
- **くっつく相手のハイライト**: 今落とそうとしているピースの隣接地域を、箱の中でオレンジ色に点滅させて地名も出す。合体ピースの中の地域も一辺14以上なら小さめの文字で地名を出す（最初は26以上で、合体すると地名がほぼ消えてくっつけられないと試遊で指摘された）
- **出す順番**: 大きすぎる地域・歪な地域（円形度 4π×面積÷周長² が低い）は、ふつうの地域を出し終えてから出す。名前のまとまり単位で判定し、上限はピース数でそれぞれ全体の15%（区画単位だと小田原市で半分近くが後回しになったため）
- **スマホ**: 箱を画面の高さにも収まるよう縮める（ヘッダー等の分として230pxを差し引く）。スクロールが必要だと試遊で指摘されたため
- **くっつく相手の引き上げ**: 落とす位置の点線に重なっている、くっつく相手のピースに重力の2.2倍の上向きの力をかけ、周りを押しのけて浮かせる（相手が山の下に埋まっていると届かないと試遊で指摘された）。狙っている間だけ効き、落とした（指を離した）瞬間にやめる（ユーザー指示）。積み直しの最中と、落とし終えて1秒間も止める（並びをばらす邪魔になったため）
- **出現位置**: 落とす・落とし直すピースは、真下にあるピースのうち一番高いものより上に出現させる。決まった高さに出現させていたため、背の高いかたまりの内側に深く重なって出現し、かたまりの中に埋まったまま残ることがあった（積み直しで起きやすかった）
- **まとめて落とす**: ピース数が多いエリアのため、次の何個かをバラバラのまま続けて落とすボタン。個数はピース数で決める（250以上で5個、500以上で10個、750以上で15個、1000以上で20個。250未満はボタンなし）。あらかじめ隣接地域をくっつけて落とす案・丁目をまとめる案は「バラバラに落としたい」とユーザーが不採用
- ボタンの並び: まとめて落とす → 積み直す → やり直す → あきらめる
- サイト共通ヘッダー（`src/components/SiteHeader.tsx`）を追加し、トップページ以外のどの画面からもトップに戻れるようにした（地図パズルのプレイ中・エリア選択の全画面表示の下には隠れる）

### 得点・ランキング

- 得点 = max(0, 合体の点 − 積み直し回数×50) ＋ 完成ボーナス（1,000点＋300秒を切った分×5点）。合体の点は合体1回ごとに「合体後のピースの地域数×10点」
- 完成時・あきらめた時に記録する（ログイン時のみ。1つも落とさずにあきらめた場合は記録しない）
- DB: `supabase/migrations/20261019000000_map_pack_schema.sql`。地図パズルと同じ「挑戦履歴（不変ログ）→ INSERTトリガーで得点をDB側で計算し直す → エリア別ベストを更新」の構成。テーブルは `game_map_pack_challenges` / `game_map_pack_best`
  - 地図パズルとは別集計にし、`game_profiles.total_score`（地図パズルの合計）には含めない。ニックネームと公開範囲（ニックネーム設定済みなら公開）は `game_profiles` を共用し、ニックネーム変更は専用トリガーで地図パックのベストにも伝播する
  - 合体の点は「全ピースを1つのかたまりに足し続けた場合」を上限としてCHECK制約で弾く。それ以外（完成したか・タイム）は自己申告（地図パズルと同じ前提）
  - テーブル・関数とも `anon` への権限を明示的にREVOKEしている（CLAUDE.md の教訓）
  - エリア別ランキングは `pref_code` と `city_code` の両方で絞る（`city_code` は都道府県内の3桁コードなので、単独だと別の県の同じコードと混ざる）
- ランキングの行はプロフィールページへのリンクにしない（地図パックのプロフィールページは無いため。`RankingList` に `profileBasePath` を追加して切り替え）

### シミュレーションで分かったこと（Node上、落とす順番・位置はランダム、跳ねる処理なし）

- 戸塚区（53ピース）: 全部落とした時点で36〜43ピース残り、積み直し4回で6〜8ピースまで減った
- 小田原市（196ピース）: 全部落とした時点で170ピース残り、積み直し4回でも87ピース残った。ピースが小さく（80ピースが最小サイズ）、合体の相手に触れにくい。1フレームあたりの物理演算は約5.4ミリ秒（PCなら問題ない水準、スマホは未確認）
