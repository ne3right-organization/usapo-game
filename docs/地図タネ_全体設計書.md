## 1. コンセプト

**現地で他の人の拠点を訪ねて、そこで育ったもののお裾分けを集めるゲーム。**

- **メインは拠点を訪ねること（決定）**。現実の町丁に置かれた拠点を訪ねると、そこで育ったもののタネを分けてもらえる。それを自分でまいて育て、収穫したもの（実）が集まっていく（2026-10-28 に、訪ねてもらえるのはタネだけ、と決めた。6.2）
- 自分も町丁に拠点を置ける。拠点は誰が訪ねても育つ
- 集めたものは、マイページの「箱庭」（ガーデン）に飾れる。**箱庭はおまけ（決定）**で、遊びの中心ではない。集めたものを眺めたり、その人がどこを訪ね何を集めてきたかが表れたりする場所

### 1.1 生まれた背景と狙い

出発点は、地域活動の現実の場面。

> 街Aに住んでいる人がいる。街Bでは仲間がポスティングなどの地域活動を続けているが、住んでいる場所が離れているので、なかなか参加できない。それでも街Bに行ったときには、みんなが育ててきたものの**お裾分け**をもらいたい。

ここから、ゲームの狙いを次のように置く。

- **その街で活動している人が育てたものを、たまに訪れた人も受け取れる**。毎回参加できなくても「たまにしか行けないけど、つながっている」関係をゲームで表す
- **面白い人に興味を持ち、そこからその人の活動（地域のボランティア）にも関心が広がる**きっかけを作る。人の個性は拠点ではなく**箱庭**で見せる（拠点に出すのは地名・置いたもの・Lv だけ。6.1）
- **現実の活動をゲームの報酬にはしない**（強制的に結びつけない）。現地に行くだけでも楽しめ、活動に参加している人には別の発見がある、くらいにする。活動との関わり方は後で考える
- 集める楽しさがあれば、ボランティアに関心がない人でも遊び始められる

### 1.2 形が決まるまで（壁打ちの経緯）

| 段階 | 出た案 | 結論 |
|---|---|---|
| ① 持ち帰ったものをどうするか | 自分の街に広がる／自分のコレクションになる／自分の街でも育てられる | **コレクション**が近い。ただし**自分の街が育たないと厳しい** → 街ごとに育てる世界があり、コレクションは街を越えて持ち運べる。遠くに行かないと進まない、にはしない |
| ② 街が育つとは何が増えることか | 木や花／建物／色や模様／動物 | 「ゲストが現地でチェックインすると、登録されたものをもらえる」ので**建物** |
| ③ もらった建物をどこに置くか | 自分の街／みんなで育てる街／両方 | 建物をもらうのではなく、**お店を開いて、そこからアイテムを持ち帰り、自分の部屋にコレクションする** |
| ④ お店とは何か | 現実のお店をゲームにする／プレイヤーがお店を開く | **プレイヤーが開く**。現実のお店は許可・店舗情報・営業への影響などで問題になるので、**単なるポイント**にする |
| ⑤ ポイントに最初に何を置くか | 木／花／ベンチ／小さな家／石碑／街灯／噴水（AIは「木と花の2択」を推した） | **最初は木を植える**。しばらく育てたら花を植えられるようになる、というように**プレイヤーも育つ**（5.4） |
| ⑥ 町丁ごとに何を作るか | 果樹を植えたところは家に、野菜や米は田畑に、木からは材木、海からは魚… | 「やりすぎか」と迷ったが、構想としては広げてよい、最初に作るものは小さく（木・畑・果樹の3つ）、となった。町丁をまたいで暮らしがつながる案や、海に面した町丁では魚、という地域性の案も出た。**後に設計から外した**（2026-10-28。生産の仕組みが要り、後半の「複雑にしない」と合わない） |
| ⑦ 後から来た人はどう開拓するか | — | **先に始めた人の畑を訪ねてタネをもらうと、自分でも開拓できる**。先に始めた人には「最初に発見した」名誉が残る（6.2） |
| ⑧ （後半） | — | 生産の仕組みは複雑にせず「**訪れたらもらえて、コピーを置ける**」程度に絞った。4つのコースができ、ポイントは「現実の町丁に置く拠点」、部屋は「マイページの箱庭」になった（2章以降） |

用語の移り変わり: 建物 → お店 → ポイント → **拠点**、部屋 → **箱庭**。

途中で出たキャッチコピー: **「日本の町丁を舞台に、みんなで少しずつ暮らしを作っていく」**。町丁単位の geojson を持つうさぽならではの形で、住んでいる人が自分の街を育て、別の地域の人が訪ねて持ち帰る。

### 設計の原則（決定）

1. **ルールは全コース共通**にし、個性は集めるアイテムと箱庭の見た目で出す。コースごとに別のゲームの仕組みや別の条件を作らない
2. **生産の仕組みは複雑にしない**。「訪ねたらもらえて、コピーを箱庭に置ける」程度にする。拠点の種類とランクごとに、もらえるものを決めておくだけにし（3.3）、生産シミュレーションはしない
3. **アイテムはデータで増やす**。新しい種類はデータと画像を足すだけで追加でき、プログラムを作り直さない
4. **外出しなくても遊べる**。位置情報のゲームだが、出かけない日も箱庭はいじれる。訪問は遊びを豊かにするもので、必須の作業にはしない
5. **後から始めた人が不利になり続けない**。基本のアイテムは後から始めた人も手に入る
6. **自分の街でも進められる**。遠くの拠点を訪ねないとゲームが進まない、にはしない（自分の拠点を育てられる）
7. **現実のお店・施設は登録しない**。拠点はプレイヤーが置く単なるポイント

## 2. ゲームの全体像

### 2.1 構成要素と役割

| 要素 | 役割 | 場所 |
|---|---|---|
| 現実の町丁 | 探索する場所 | 現実（うさぽの町丁ポリゴン） |
| 自分の拠点 | 自分で開き、訪ねられて育つ場所 | 現実の町丁に紐づく |
| 他の人の拠点 | 新しいアイテムに出会う場所（**遊びの中心**） | 現実の町丁に紐づく |
| マイページの箱庭 | 集めたものを飾る場所（おまけ） | ゲーム内（1人1つ） |
| プレイヤーレベル | 新しいアイテムを解放する仕組み | — |

拠点は何十か所でも持てるが、それぞれに作り込んだ箱庭は作らない。作り込むのはマイページの箱庭1つだけ。**拠点と箱庭は別のデータとして扱い、拠点に置いたアイテムをそのまま箱庭の配置として扱わない。**

### 2.2 コアループ

```
 レベルアップでアイテムを解放
        │
        ▼
 自分の拠点(現実の町丁)に置く ──→ 時間とともに育つ ──→ 収穫物ができる
        │                              ▲
        │                              │ 誰かが訪ねると育つ(持ち主も他の人も同じ)
        ▼
 他の人の拠点を訪ねる ──→ そこのタネを分けてもらう ──→ 自分でまいて育て、収穫して実を集める
        │
        ▼
 マイページの箱庭に飾る(持っている数まで)
        │
        ▼
 たずねた拠点の数でレベルが上がる ──→ 先頭に戻る
```

育成・探索・収集・表現の4つが1つの流れでつながる。

## 3. コース

### 3.1 ルール（決定）

- 始めるときに5つのコースから1つ選ぶ。**コースが決めるのは、最初の拠点の種類と、レベルで解放される拠点の種類の方向だけ**
- **拠点の種類は1レベルに1つ、それぞれにタネが3つある（決定。3.3）**。例: 果樹園（Lv.1）のタネは みかんの木・梨の木・いちご畑
- **拠点を作るには、タネ（持ち物）を1つ使う（決定。6.4）**。梨の木のタネをまくと果樹園ができ、訪ねた人は梨の木のタネを分けてもらう。持っていれば、種類やレベル・コースの制限なくまける
- **レベルが上がると、自分のコースのそのレベルの種類のタネ3つを1個ずつもらえる（決定）**。始めたときは Lv.1 の種類のタネ3つを1個ずつ持っている（たずねる → レベルが上がる → 新しいタネをまける、でメインの訪問とつながる）
- **拠点の呼び名は種類によって変わる（決定）**。果樹園・田んぼ・港など（3.3）
- 他の人の拠点を訪ねれば、**自分のコース以外のものも手に入る**
- 箱庭には、どのコースのものでも混ぜて飾れる
- コースによって成長速度などを変える設定はしない

役割分担: **自分のコースは個性、訪問は発見、箱庭は表現。**

### 3.2 5つのコースと世界観

| コース | 世界観 |
|---|---|
| 🌿 植物 | 庭・森・畑を育てる |
| 🐾 動物 | 自分だけの動物園・牧場 |
| 🎨 趣味 | 趣味の道具やコレクションを集める |
| 🚗 乗り物 | ガレージ・駅・港・宇宙基地 |
| 🏠 建物 | お店や町の建物。壁打ちで一度出た「お店を開いて、そこからアイテムを持ち帰る」案を生かしたもの |

- 動物コースは動物を集める楽しさが中心。**現実の動物を捕まえるのではなく**、ゲームの中で出会ったり、拠点に迎えたりする設定にする

経緯: 最初は「ガジェット」コース（ロボット・作業台・ソーラーパネル…）だったが、工場を作るゲームのようで趣味の箱庭らしくないため、**趣味コースに作り替え**、**乗り物コースを足して**4つにした。そのあと**建物コースを足して5つ**にした（2026-10-28）。

### 3.3 コースの表

**5コース × 拠点の種類10（Lv.1〜10 で1つずつ）× 種類ごとのタネ3つ（決定）**。もらえるものは、そのまま箱庭に置ける形のもの（決定）。

- 拠点の種類は1レベルに1つ。そのレベルになると、その種類のタネ3つを1個ずつもらえる（3.1）
- タネ1つが、もらえるもの1つに当たる（梨の木のタネ → 梨の木）。**3つは色違いでもよい（決定）**（例: 赤・黄・白のチューリップ）。絵は1つの形を3色に塗り分ければ済む（10.4 の方法A）
- 拠点に出す「Lv」（6.1）は、この拠点のランク（育ち具合）。訪ねられて育つと上がる（5.1）。育ったときに見た目やもらえるものがどう変わるかは、詳細を詰める（13章）
- 全部そろえると 5 × 10 × 3 = **150点**（色違いにすれば、形は50種類）。**最初から全部は作らない（決定）**: コースの表はコードの中のデータなので、足すのは表への1行と絵だけで済む

| 🏠 パン屋 | 食パン → メロンパン → あんぱん → クロワッサン → カレーパン → バゲット → パン屋の看板 → 石窯 → パン屋の店先 → 町いちばんのパン屋 |

- 並べ方は2通りある: **身近なもの → 珍しいもの**（小鳥・果樹）と、**小物 → 建物**（パン屋・星見台）。小物から建物になる並びは、ランクが上がるほど箱庭で大きく見栄えがし、上げた手応えが伝わる
- 果樹園は、壁打ちのあとで出た例（みかん → 梨 → イチゴ）をそのまま使った
- 壁打ちの案のうち表に入らなかったもの（小さな苗木・猫・ミニカー・ロケットなど）は、種類や段階を詰めるときの候補にする

#### 10段階を間延びさせない工夫（案）

- **節目で拠点の呼び名が変わる**: ランク5で「果樹園」→「大きな果樹園」、ランク10で「名所の果樹園」のように変わり、地図での見た目も変わる（節目だけなので絵の手間は少ない）
- **ランク10は特別**: その地区の「名所」として地図で目立たせる。「訪ねられ続けると姿が変わる」（5.5）の行き着く先
- **レベルが上がる訪問数を後ろほど長くする**: 例: Lv.2 は3か所、Lv.3 は6か所……Lv.10 は100か所。レベルは「たずねた拠点の数」で決まるので、後半ほど遠出が要る

## 4. アイテム

### 4.1 データの考え方（決定）

- **アイテムの定義**（名前・コース・画像・解放レベル・入手方法…）と、**プレイヤーが持っているアイテム**を分ける。絵を描き直せば、全員の箱庭に反映される
- **拠点に置いたアイテム**と**集めて持っているアイテム**も別物として扱う。分けておくと後でルールを変えやすい
- 入手方法はデータとして持ち、入手方法ごとに専用の処理を増やさない

アイテム定義に持たせる項目（例）:

| 項目 | 例 |
|---|---|
| アイテムID | `tree_001` |
| コース（属性） | 植物 |
| 解放レベル | 1 |
| 設置可能数 | 制限なし、または上限あり |
| 入手方法 | 初期配布・拠点訪問・収穫 など |

### 4.2 入手方法

| 入手方法 | 内容 | 段階 |
|---|---|---|
| 初期配布 | コースに応じた最初のアイテム | 初期試作〜 |
| レベルアップ | 自分のコースの新しいアイテムを解放 | フェーズ4〜 |
| 自分の拠点で収穫 | 育ったアイテムから収穫物 | フェーズ5〜 |
| 他の人の拠点を訪問 | アイテム（実）はもらえない。その拠点のタネをもらい、自分で育てて収穫する（コース外も可） | 初期試作〜 |
| イベント・期間限定 | 配布 | 未定 |
| 他の人との交換 | — | 将来 |

### 4.3 収穫

収穫したもの（実）は、どれも箱庭に置ける形にする（3.3）。**アイテム（実）が手に入るのは、実った拠点で実をもらったときだけ（5.5。2026-10-29 に決定）**。訪ねてもらえるのはタネで、実は実った拠点に行かないと手に入らない。実の名前と絵は、いまはタネと同じもの（梨の木のタネ → 梨の木）の仮のまま。

**実には産地の名前が付く（2026-10-29 に決定）**。「戸塚区矢部町のりんご」のように、実をもらった地区の名前で呼ぶ。どこの実を集めたかが記録に残り、たずね歩くことと結びつく。

- 一覧では「市区町村名＋町名」の短い名前（政令市は区の名前だけ）。同じ短い名前の産地が2つあるとき（よその県の同じ名前の区・町）は、都道府県から全部出す。詳細では、いつでも都道府県から全部出す
- 詳細では、実がなった日・収穫した日・生産者（そのタネをまいた人）を出す。**生産者はフレンド（お互いにフォローしている人）のときだけ**見せ、それ以外は「ひみつ」にする
- 数えるのは地区のコードなので、名前が同じでも別の産地として数える
- 箱庭に飾るのは、いまは実の種類単位（産地は問わない）

**タネと実は別のもの（決定）**。タネはまくための持ち物で、集めたもの・箱庭には入らない。画面でも、タネはタネ袋の絵（何のタネかを小さく出す）にして、実の絵と見分けられるようにする。テストで、訪ねてタネをもらっただけでコレクションしたことになるのはおかしい、という声があったため（それまでは訪ねると実とタネの両方がもらえた）。

### 4.4 「コピーして置ける」の意味

訪問や収穫で手に入れたアイテムは、箱庭に**コピーとして**置く（拠点のアイテムそのものを持ってくるわけではない）。

**箱庭に置けるのは所持数まで（決定）。** 同じアイテムをたくさん置きたければ、何度も訪ねたり収穫したりして数を増やす。初期試作もこの形で作る（初期試作設計書 4章）。

## 5. 成長

### 5.1 成長の3つの軸（決定。最初はこの3つだけ作る）

1. **時間とともに育つ**: 苗木 → 若木 → 立派な木。毎日ログインしなくても少しずつ育つ（忙しい人も自分のペースで遊べる）
2. **訪ねられると育つ**: 拠点にチェックインがあると成長ポイントが入り、一定に達すると次の段階に進む。**拠点は作った人のものだが、育ち方は誰が訪ねても等しい（決定）**。持ち主が通っても、仲間や遠くから来た人が訪ねても同じだけ育つので、同じ街の仲間がそれぞれ訪ねることで、みんなで1つの拠点を育てる形になる（1.1 の「仲間が育てたもののお裾分け」）。毎日通う義務にはしない
3. **集めると置けるものが増える**: 他の人の拠点で見つけたアイテムが、自分の箱庭に置けるようになる

**育ち方の決まり（2026-10-29 に決定。試作に入れた）**

- **タネ → 芽 → 若葉 → つぼみ → 花 → 実り** の6段階で育つ（`src/lib/game/chizuTane/growth.ts`）
- **時間では育たず、必ず水をやって育つ**。芽が出るのも水で、まいた直後から水をやれる。上の1（時間とともに育つ）は、試作ではやめた
- **現地のチェックインは水やりと同じ**。持ち主でもほかの人でも、1つの拠点に1人1日1回。水は1回で10たまる
- **持ち主は、自分の拠点に遠くからも水をやれる**。拠点ごとに1日1回で、効き目は現地の10分の1（1回で1）。現地に行けない日の世話になる（原則4・6）
- 水が50たまる（現地なら5回、遠くからなら50回）と実る。画面には「あと現地で○回（遠くからなら○回）水をやると実ります」と出す
- 実ると、その拠点に**実が10個なる**（5.5）
- 数（10・1・50・10個）は仮
- 経緯: 試してくれた人から「牧場物語のような成長要素が欲しい」という声があり、2026-10-28 に「1日たつと1段階、チェックインでさらに1段階」の形で入れた。翌日、タネ・水・実の動きを整理し直して今の形にした

### 5.2 何が育つか（決定）

**育つのは現地の拠点に置いたアイテムだけ。箱庭のアイテムは育たず、飾るだけ。** 拠点のアイテムが育って収穫物を生み、マイページの箱庭はそれを飾る場所、という分担にする。大きな木を箱庭に置きたければ、拠点で育てて「大きな木」を手に入れる。

### 5.3 プレイヤーレベル

- アイテムの成長とは別に、プレイヤー自身のレベルを持つ。レベルが上がると新しいアイテムが解放される（3.3）
- **レベルは、たずねた拠点の数と、いまのタネを全部まいたかで上がる（決定）**。Lv.n から上がるには、ほかの人の拠点を決まった数たずねていて、かつ自分のコースの Lv.n の種類のタネ3つを一度はまいていること（2026-10-28 に足した条件。まかずに次々レベルが上がって、タネが手元にたまっていくのを防ぐ）。同じ拠点は何度たずねても1つと数える。シンプルで分かりやすく、毎日のログインや同じ拠点の往復では上がらない。何か所でレベルが上がるかは未定（試作では1か所で Lv.2、3か所で Lv.3）
- レベルが上がると、自分のコースのそのレベルの種類のタネ3つを1個ずつもらえる（3.1）。まくのにレベルの制限は無い

### 5.4 プレイヤーと拠点が一緒に育つ

最初から複雑なことはできず、育てるうちに「今までできなかったことができるようになる」。操作も少しずつ覚えられ、開発側も最初は木と花だけ作って後から増やせる。

| 段階 | できること | プレイヤーの変化 |
|---|---|---|
| 🌱 はじまり | 木を1本植える | 町丁に自分の拠点ができる |
| 🌿 成長 | 木が大きくなる | 花を植えられるようになる |
| 🌼 発展 | 花壇を作る | ベンチなどの家具を置ける |
| 🌳 充実 | 木や花を組み合わせる | 小さな庭を自分らしく飾れる |
| 🏡 熟練 | いろいろな景観を作る | 珍しい植物や飾りが解放される |

**最初は一本の木。それがいつか、自分だけの小さな庭になる。** この成長の物語を軸にする。

> この段階表は、壁打ちで出た「一緒に育つ」物語のイメージ（植物の例）。実際の仕組みは 3.3 のとおりで、プレイヤーはレベルで新しい拠点の種類を解放し、拠点はランクで育つ。最初の拠点は自分のコースの1種類目（果樹園のみかんの木、小鳥の林のすずめ、撮影スポットのカメラ、サイクルポートの自転車、パン屋の食パン）から始まる。

### 5.5 育ちきったあと（決定）

拠点が育ちきって変化が止まると面白くない。育つのが止まっても、拠点に通う理由・人に来てもらう理由が続くようにする。

1. **実ったら、実が10個なり、来た人が誰でも1個ずつもらえる（2026-10-29 に決定）**: 実ると、その拠点のもの（実。4.3）が10個なる。現地でチェックインした人は、持ち主でもほかの人でも1個もらえる（1人1日1回、早い者勝ち）。実があるうちは、水をやっても変わらない（当分の間はそのまま）。**10個なくなったら芽に戻り、ランクが1つ上がる**（10まで）。水をやって育てた人みんなに見返りがあり、「育つのが終わり」ではなく、育てて実をもらうのを繰り返す。数は仮（`growth.ts` の `FRUITS_WHEN_RIPE`）。ランクが上がったときに何が変わるかは未決（13章）
   - 前日（2026-10-28）は「持ち主が現地で収穫して、実3つとタネ1個」だったが、育てるのを手伝った人に見返りが無いので変えた
2. **訪ねられ続けると姿が変わる**: 最後の段階まで育ったあとも、訪ねてくれた人の数で見た目が変わっていく（足あとが増える、ベンチが置かれる、ちょっとした名所になる、など）。拠点を置いた人には「人に来てもらう」ことが目標になり、1.1 の狙い（人への興味・つながり）にそのまま合う
3. **季節で姿が変わる**: 春は花、秋は紅葉、というように現実の暦に合わせて見た目が変わる。同じ形の色違い（10.4 の方法A）で作れるので絵の手間が少なく、「また行ってみよう」の理由にもなる

**枯れる仕組みは入れない。** 世話をしないと枯れるようにすると、なかなか現地に行けない人を罰することになり、出発点（1.1）と原則4・6に反する。

## 6. 現地拠点

### 6.1 登録

現地で、ブラウザの位置情報を使って拠点を登録する。**写真は使わない（決定）**（写り込みや場所の特定の心配、画像の保存・確認の手間を避ける）。

- ブラウザの位置情報（GPS）で位置を取り、うさぽの町丁ポリゴンからどの地区（町丁）にいるかを判定する
- 位置情報には誤差があるので、判定結果だけで決めず、**判定した地区をプレイヤーに見せて確認してから登録する**
- **拠点は1つの地区に1つだけ、早い者勝ち（決定）**。壁打ちの「町丁に一つの拠点」のとおり。地区ごとに拠点が決まるので地図が分かりやすい
  - 後から始めた人が不利になりすぎないか（原則5）: 町丁は全国に十数万あり、置き場所が尽きることはまず無い。また拠点は誰が訪ねても同じだけ育ち（5.1）、タネは訪ねればもらえる（6.2）ので、人の多い地区を先に取られても遊びは成り立つ
- **拠点の場所は地区として扱い、地区の中の細かい位置は持たない・見せない（決定）**。拠点に出すのは、地名（「○○町」など）・置いたものの種類・Lv だけ。置いた人のニックネームや紹介文も出さない（人の個性は箱庭で見せる）
  - 地区の中の特定の場所に人を呼び寄せないので、私有地や学校などに誘導する心配がなく、写真も文章も無いので、通報の仕組みも初期版では要らない
- 登録するときに、持っているタネから1つ選んでまく（タネは1つ減る。6.4）。拠点はランク1から始まる（植物の果樹園なら、最初はみかんの木）。そこから少しずつ景色が変わっていく

### 6.2 訪問

- 他の人の拠点を訪ねると、そこのタネを分けてもらえる。自分がまだ持っていない種類のタネを見つける楽しみ
- 先に始めた人が育てたアイテムをきっかけに、後から始めた人も新しい開拓を始められる
- **タネで開拓が広がる**: 先に始めた人の畑や果樹を訪ねてタネをもらうと、自分の拠点でもそれを育てられるようになる。今度はその人が別の人にタネを渡せる。ゲームの進み方が、個人のレベルアップだけでなく**プレイヤー同士のつながり**で決まる
  - 先に始めた人の価値は、ランキングの上位ではなく「まだ誰も持っていないタネを広める存在」であること（例: ある地域で初めて稲を育てた人の拠点を訪ねたことで、別の地域にも稲作が広がる）
  - ただしタネは訪ねれば簡単に手に入るようにし、先に始めた人には「**最初に発見した**」名誉だけが残る（原則5）。人が少ない時期は一人でも遊べ、人が増えるほど遊び方が広がる
- **もらえるのは現地でチェックインしたときだけ（決定）**。**拠点のある地区の中にいれば、どこからでもチェックインできる（決定）**。地図からは他の人の拠点を見たり応援したりするところまで。自分の拠点を育てることと箱庭づくりは、家からでもできる（原則4・6）
- **訪ねると、まかれたタネを1個分けてもらえる**（梨の木のタネの果樹園なら梨の木のタネ）。同じ果樹園でも、まかれたタネによってもらえるタネが違う（みかんの木・梨の木・いちご畑）。**タネをもらえるのは、その拠点に初めてチェックインしたときの1回だけ（2026-10-29 に決定）**。2回目からのチェックインは水やり（5.1）。実はもらえない（実った拠点で実をもらうときを除く。5.5）
  - 当初は「拠点が育つと みかん → 梨 → イチゴ ともらえるものがランクアップする」案だったが、みかん・梨・イチゴは果樹園の3つのタネになった（2026-10-28）。拠点が育ったときに何が変わるかは詳細を詰める（13章）
- **同じ拠点にチェックインできるのは1日1回（決定）**。その場で何度もチェックインして水や実を増やすことはできない。地元の人は毎日の通り道で少しずつ、遠くから来た人はその日にいくつもの拠点を回って集める

### 6.3 拠点と箱庭の違い

| 項目 | 現地拠点 | マイページの箱庭 |
|---|---|---|
| 目的 | 訪問・発見・アイテムの獲得・育成 | コレクション・装飾・表現 |
| 位置 | 現実の位置（町丁） | ゲーム内の仮想空間 |
| 数 | 1人で複数 | 1人1つ |
| 所有者 | 拠点を登録した人 | プレイヤー本人 |
| アイテムの置き方 | 拠点の状態に応じた配置 | 自由な配置 |
| 訪問 | 位置情報と連携 | 不要 |

### 6.4 タネ（持ち物。決定）

壁打ちで「無限にタネをまける」と地区を独り占めできてしまう、と気づいたので、タネを持ち物にした。**タネは「もの」ごと**（みかんの木のタネ、梨の木のタネ…）で、**まくと1つ減る**。これで地区の独り占めを防ぎ、「訪ねてタネをもらう → まく」でメインの訪問とつながる。

| いつ | 増えるタネ |
|---|---|
| 始めたとき | 自分のコースの Lv.1 の種類のタネ3つを1個ずつ（例: みかんの木・梨の木・いちご畑。最初の持ち物はタネだけで、飾るものは持たない） |
| レベルが上がったとき | 自分のコースのそのレベルの種類のタネ3つを1個ずつ |
| ほかの人の拠点に初めてチェックインしたとき（拠点ごとに1回だけ） | まかれていたタネと同じものを1個（ほかのコースのタネも手に入り、人から人へ広がる。6.2） |
| 拠点に落ちているタネを拾ったとき | 落ちていた分（下） |

- **ほかの人が初めてチェックインしたとき（タネをもらったとき）に、その拠点にもタネが1個落ちる**。落ちていられるのは3個まで。落ちているタネは**誰でも（持ち主でもほかの人でも、自分が落とした分も）早い者勝ちで拾える**。持ち主のチェックインでは落ちない（自分で落として自分で拾えると、毎日タネが増えてしまうため）。2026-10-29 にタネを「初めての1回だけ」にしたのに合わせて、落ちるのも初めてのときだけにした（仮）
- **拾う数は選べる（決定）**。「1個拾う／2個拾う…」から選び、拾わなければそのまま残る（次の人のために残しておける）
- **持ち主の手元に直接タネが増えることは無い（決定）**。人が来てくれた拠点ほどタネが落ちているので、拾いに行く理由になる（現地に行かないとタネは増えない）
- **時間がたつだけでタネが増えることは無い（決定）**。誰かが来てチェックインしないと増えない
- **まいた直後から、自分もほかの人もチェックイン（水やり）できる（2026-10-29 に決定）**。芽が出るのも水で決まる（5.1）。それまでは「まいてから24時間は芽が出ておらず、チェックインできない」としていた（まいた直後に自分でお裾分けをもらうのが不自然だったため）が、自分のチェックインで何かがもらえることは無くなったので、待つ理由が無くなった
- 自分の拠点へのチェックインは水やり、実っていれば実を1個もらう（5.1・5.5）。訪問の記録に残さず、レベル（たずねた拠点の数）にも数えない
- まくのに、種類・コース・レベルの制限は無い。持っていればまける

経緯（2026-10-28）: 最初は「人が来ると持ち主に2個・持ち主が訪ねると1個・誰も来ないまま3日ごとに1個」が持ち主の手元に増える形だったが、試してみると、離れた場所で勝手にタネが増えるのは違うと分かり、「拠点に落ちていて、現地で拾う」形にした。

その次は「自分の拠点にチェックインしてもタネが1個もらえ、1個落ちる」形だったが、テストでは「まく → 芽が出たら自分でチェックイン → タネが増える → またまく」の繰り返しで、30分足らずで1人が数十個まいていた（dev の芽が出るまでの5分と開発用の位置指定のせいもある）。持っている拠点が多いほど毎日のタネも増えるので、本番でも時間がたつと同じことが起きる。そこで自分の拠点へのチェックインは水やりにした。さらに 2026-10-29 に、ほかの人の拠点でもタネは初めての1回だけにした。

## 8. 他の人とのつながり

- 他の人の箱庭を見られるようにして、人への興味につなげる（1.1 の狙い）
- 他の人の拠点を訪ねることが、そのままアイテムとの出会いになる
- **全国のタネ地図（2026-10-28 に決定）**（画面の名前は「全国農地」。2026-10-29）: 全国のどこに拠点があるかを地図に点で出す。訪ねるのがメインなので、どこへ行けば拠点があるかが分からないと遊べない（テストで、離れた所の人が置いた拠点を探しようがなかった）。点は**地区の代表点**（geojson の X_CODE / Y_CODE）に出し、まいた人の実際の位置は持たない・出さない（6.1）。持ち主の名前も出さない（どこに住んでいるかが分かってしまわないように）。試作では全件を読むので、拠点が増えたら都道府県・市区町村ごとの数をまとめる形に変える
- 交換は将来
- **地域ごとの合計やコンプリート（全部の拠点を回る、など）は作らない（決定）**。現実の位置情報が絡むので、全部回ることを目標にするのは無理がある。他のゲームにある「コンプリート状況」の地図とはつなげない

> usapo-game には全ゲーム共通のニックネームとフォローがすでにある。他の人の箱庭の公開は、既存のゲームと同じく「ニックネームを設定した人だけ」に合わせるのが自然。

## 10. デザイン（画像素材）

**このゲームで一番の難所は、プログラムより「絵柄をそろえて、集めたくなる世界を作れるか」。** だから仕組みを作り込む前に、AI で作った少数の素材を実際に並べて確かめる（初期試作と並行して進める。初期試作設計書 10章）。

### 10.1 進め方

- **ルールを先に決め、画像は後**。画像を大量に作ったあとでルールが変わると無駄になる
- 最初は10種類以内から始める。壁打ちでの植物コースの例: 木・花・果樹・野菜・稲（置くもの）、木材・果物・野菜の収穫物（集めるもの）、ベンチ・小さな家（飾り）
- 3D は使わず、**斜め上から見下ろす、立体感のある2D** の箱庭にする（小さな正方形の土地に透過PNGのアイテムを置く）。カメラ・照明・物理演算を管理せずに済み、Next.js の Web ゲームで作れる

### 10.2 AI で作るもの・プログラムで作るもの

AI が作った箱庭の完成イメージをそのまま使っても、木を動かしたり猫を足したりはできない。完成イメージと、ゲームの中で動かせる箱庭は別物として分ける。

| 作るもの | 方法 |
|---|---|
| 箱庭の完成イメージ（雰囲気の検討用） | 画像生成AI |
| 木・花・猫・車などのアイテム | 画像生成AIで1つずつ作る |
| 箱庭への配置・移動 | ゲームのプログラム |
| レベルアップでの解放 | ゲームのデータとプログラム |
| アイテムの成長・収穫 | ゲームのデータとプログラム |

### 10.3 AI で素材をそろえるコツ

AI は1枚ずつの絵は得意だが、数十種類を同じルールでそろえるには工夫が要る。

- **絵柄をそろえる**: 植物だけ写実的で車だけアニメ調、だと並べたときに浮く
- **背景を透過する**: アイテムだけを切り出して置けるようにする
- **向き・形をそろえる**: 同じ視点から見た絵にする
- 最初に「このゲームの標準デザイン」を1つ決めて固定し、その指示で木・花・猫・車・望遠鏡…と順に作る。壁打ちでの例: 「かわいいローポリ風、柔らかい色合い、斜め上からの視点、輪郭はシンプル、ゲーム用アイテム、背景透過」（ミニチュア風にするかローポリ風にするかは試して決める。初期試作設計書 10章）
- 生成した絵はそのまま使わず、大きさ・視点・透明部分を確かめて直す（確認項目は初期試作設計書 10.3）

### 10.4 素材を減らす工夫

- **A. 同じ形で状態を変える**: 若木・成長した木・花が咲いた木・実がなった木を、色・大きさ・飾りの違いで描き分ける（成長の段階表示にもそのまま使える）
- **B. 小さな部品を組み合わせる**: 木・花・石・ベンチなどを並べて景観を作る
- **C. 箱庭の画面をシンプルにする**: 作り込んだ世界は目指さない。小さな区画に置くだけでも、集めて並べる楽しさは出せる

## 12. usapo-game の基盤への当てはめ（概要）

| 必要なもの | 既存の基盤 | 新しく要るもの |
|---|---|---|
| ログイン・ユーザーID | Cognito（Google）・`sub` | — |
| ニックネーム・フォロー | `GameProfile`・`GameFollow` | — |
| データ・信用の要る書き込み | Amplify Data ＋ Lambda のカスタムミューテーション | 箱庭・所持・拠点・訪問のモデルと Lambda |
| 町丁の判定 | CloudFront の町丁 geojson | ブラウザでの位置取得、点がどのポリゴンに入るかの判定。geojson は大きいので、その都道府県・市区町村の分だけ読む |
| 訪問・チェックインの確かさ | 無い | 位置はブラウザの自己申告なので厳密には防げない。**直前のチェックインからあり得ない速さで移動していたら断る、だけをサーバー（Lambda）で確かめる（決定）**。ランキングが無いので、不正で得をするのは本人だけ。**開発・テスト用に、位置を手で指定できる仕組みを用意する**（dev 環境・手元だけで有効にし、本番では使えないようにする） |
| 時間での成長 | 無い | 定期処理はせず、読むときに「植えた日時からの経過」で段階を計算する方式が安く済む |

- 現実の位置情報を扱うのは usapo-game では初めて。チェックインの位置は判定に使うだけで、地区より細かい位置は保存しない。拠点も地区単位なので、他の人に細かい位置が見えることはない（6.1）

## 13. 未決事項

**アイテム・数値を作るときに決めること**

- 拠点のランク（収穫するたびに上がる。5.5）で何が変わるか（見た目だけか、収穫やお裾分けが増えるか。3.3 の「拠点が育ったとき」の案は、タネの仕組みを決める前のもの）
- 水の量と実の数（試作は 現地10・遠く1・50で実る・実10個）

- コースの表（3.3）の詳細: 拠点の種類と、ランク4〜10の並び（絵を作り始める前に見直す）。節目での呼び名の変化やランク10の扱い（3.3 の工夫の案）を採るか
- 何か所たずねるとレベルが上がるか（5.3）、拠点が何回訪ねられると次の段階に育つか（5.1）

**ゲームが育ってから考えること**

- 遊ばなくなった人の拠点が地図に残り続ける問題（引き継ぎ・整理の決まり）。1つの地区に拠点は1つなので、放置された拠点はその地区をふさぐ。起こり得るが、利用者が増えてから考える
- 通報・削除の仕組み（写真・文章・細かい位置を持たないので初期版では要らないが、拠点に名前を付けるなど自由入力を足すときには要る）
