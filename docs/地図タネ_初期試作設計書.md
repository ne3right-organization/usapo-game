## 1. 試作で確かめること

**「現地に行って、他の人の拠点からもらう」が楽しいか。** メインは拠点を訪ねることで、箱庭はおまけ（全体設計書 1章）。

このゲームならではの部分は「現地でもらう」ところにある。最初は成長・ランクアップ・レベルは入れずに、「拠点を置く → 他の人の拠点を訪ねてもらう → 集めたものを見る・飾る」の一周を最小限の形で通し、dev 環境（devgame.usapo.net）で実際に街を歩いて試す。試しながら、レベル・拠点の成長と収穫・全国の全国農地を足した（2026-10-28）。

確かめたい問い（大事な順）:

1. 地区に拠点を置き、別の地区で他の人の拠点にチェックインする、という流れが分かりやすいか。「他の人の拠点に行ってみたい」と思えるか
2. ブラウザの位置情報で、地区の判定が実用になるか（誤差、境界付近、スマホでの許可の出し方）
3. もらったものを集めて眺める・箱庭に飾るのが、ご褒美としてうれしいか
4. スマホで操作しやすいか

絵柄（全体設計書 10章の「一番の難所」）は、コードとは別に並行して確かめる（10章）。

## 2. 範囲

### 作るもの

| 機能 | 内容 |
|---|---|
| コース選び | 初めて開いたときに5つから選ぶ |
| おでかけ（いまいる地区） | 位置情報から地区を判定して、地名とその市区町村の地図（拠点のある地区に印）を出す |
| 拠点を置く | いまいる地区に拠点が無ければ、持っているタネを1つ使って置ける（1地区1つ・早い者勝ち） |
| タネ | 持ち物。始めたとき・レベルが上がったとき・拠点に落ちているタネを拾ったときに増える。ほかの人のタネに初めてチェックインすると、そこにタネが1個落ちる（全体設計書 6.4） |
| レベル | たずねた（もらったことのある）ほかの人の拠点の数で上がる。Lv.10 まで（はじめは Lv.3 までだった。2026-10-29 に開放） |
| チェックイン | いまいる地区に拠点があれば、チェックインする（拠点ごとに1人1日1回）。チェックインは水やりと同じで、実っていれば実を1個もらう（誰でも）。他の人の拠点に初めて来たときだけタネを1個もらえ、拠点にもタネが1個落ちて誰でも拾える |
| 遠くからの水やり | 持ち主は、トップの「あなたがまいたタネ」から自分のタネに水をやれる（拠点ごとに1日1回、効き目は現地の10分の1） |
| 集めたもの | 持っているものの一覧。実は産地ごとに「戸塚区矢部町のりんご」のように呼ぶ |
| 箱庭（おまけ） | 持っているものを、所持数まで置く・動かす・しまう。保存して次回も同じ状態で出す |
| 開発用の位置指定 | dev 環境と手元だけ、地図をタップして「いまいる場所」を指定できる（9章） |
| 育つ・収穫 | まいたタネが 芽 → 若葉 → つぼみ → 花 → 実り と育ち、実ったら持ち主が現地で収穫する |
| 全国農地 | 全国のタネを地区の代表点に点で出す |

### 作らないもの（全体設計書の後のフェーズ）

- 季節で姿が変わる・ランクが上がったときの見た目の変化
- Lv.4 以上（試作で使う拠点の種類は各コース Lv.1〜3 の3種類）
- 合成・交換
- 他の人の箱庭を見る
- 未ログインでの利用（試作はログイン必須）

## 3. 一周の流れ

```
 初めて開く ─→ コースを選ぶ(例: 乗り物)
              ─→ Lv.1 のサイクルポートのタネ3つ(自転車・マウンテンバイク・タンデム自転車)を1個ずつ持って始まる(ガーデンは空)
                                            │
 ┌──────────────────────────────────────────┘
 ▼
「おでかけ」を開く ─→ 位置情報で地区を判定(例: ○○町)
 │
 ├─ この地区にタネが無い ─→ 持っているタネ(例: 自転車のタネ)を選んで[タネをまく](1つ減る)
 │                          ─→ ここが「○○町のサイクルポート」になる(まいた直後から水をやれる)
 │
 ├─ タネがある(自分のでも他の人のでも同じ) ─→ [チェックイン](1日1回) ─→ 水をやる(実ったら実が10個なる)
 │                          / 実っていれば実を1個もらう(実がなくなったらタネ待ちになってランクが上がる)
 │
 ├─ 他の人のタネがある ─→ [チェックイン](1日1回)
 │                          ─→ 水をやる(実っていれば実を1個もらう)
 │                          ・初めてなら、その果樹園にみかんの木のタネが1個落ちる(3個まで。直接はもらわない)
 │                          ・他の人のタネに初めてチェックインして、たずねたタネの数でレベルが上がると、
 │                            次のレベルの種類(ガレージ)のタネ3つを1個ずつもらえる
 │                          (このタネからは今日はもうもらえない)
 │
 └─ 落ちているタネがある ─→ [1個拾う/2個拾う…] ─→ 選んだ数だけ拾える(誰でも早い者勝ち。拾わなければ残る)
 ▼
「集めたもの」で眺める ─→ (おまけ)「ガーデン」にみかんの木などを並べて保存
```

## 4. ルール（試作での形）

全体設計書の決定のうち、試作に入るものと、試作だけの簡略化。

| 項目 | 試作での形 | 全体設計書 |
|---|---|---|
| コース | 5つ（植物・動物・趣味・乗り物・建物）から1つ選ぶ。あとから変えられない | 3章 |
| 拠点の種類 | まくタネで決まる（梨の木のタネ → 果樹園）。持っているタネから選ぶ（種類・コース・レベルの制限なし） | 3.1・6.4 |
| タネ | 「もの」ごと（みかんの木のタネ…）。まくと1つ減る。始めたとき Lv.1 の種類のタネ3つを1個ずつ、レベルが上がるとそのレベルの種類のタネ3つを1個ずつ、拠点に落ちているタネを拾うと拾った分（誰でも早い者勝ち。3個まで）。ほかの人の拠点に初めてチェックインすると、そこに1個落ちる | 6.4 |
| レベル | 上がるには (1) ほかの人の拠点を決まった数たずねる（Lv.2 5か所 / Lv.3 12 / Lv.4 25 / Lv.5 40 / Lv.6 60 / Lv.7 90 / Lv.8 130 / Lv.9 180 / Lv.10 250。`courses.ts` の `TANE_LEVEL_THRESHOLDS`。2026-10-29 に厳しくした。それまでは1か所で Lv.2、3か所で Lv.3）と (2) いまのレベルのタネ3つを全部まく、の両方。チェックインとタネをまいたときに確かめる。Lv.10 が上限 | 5.3 |
| 拠点の育ち方 | 必ず水をやって タネ → 芽 → 若葉 → つぼみ → 花 → 実り と育つ（時間では育たない。芽が出るのも水）。現地のチェックインで水10、遠くからの水やりで1。50で実る | 5.1 |
| 実・ランク | 実ると実がなり（ランク×10個）、持ち主に生産者の取り分が1個届く（誰が実らせても。遠くからの水やりでも）。現地でチェックインした人は誰でも1個もらえる（早い者勝ち。現地で水をやって実らせた人はそのまま1個）。実がなくなったらランクが1つ上がり（10まで）、タネ待ちになる。持ち主が同じ種類の畑のタネをまき直すと、またタネから育つ（遠くからでもよい）。1週間まかないと空き地に戻る。ランクが上がると実の数が増える | 5.5 |
| もらえるもの | まかれていたタネのもの（梨の木のタネの果樹園なら梨の木）を1つ | 3.3・6.2 |
| 最初に持つもの | 自分のコースの Lv.1 の種類のタネ3つを1個ずつ（飾るものは持たない） | 3.1・6.4 |
| 拠点を置ける場所 | 1地区に1つ、早い者勝ち。1人で置ける数は制限なし（地区が違えばいくつでも） | 6.1 |
| チェックインできる場所 | 拠点のある地区の中ならどこでも | 6.2 |
| 1日の区切り | チェックイン・遠くからの水やりは、本番は日本時間の朝（4〜12時）・昼（12〜20時）・夜（20〜翌4時）にそれぞれ1回（2026-10-29 に1日1回から変えた）。dev（devgame.usapo.net・手元）は試しやすいように5分ごとに区切る（`geo.ts` の `slotKey`、Lambda の `CHIZU_TANE_DAY_MS`）。芽が出るまでの待ち時間は無い（まいた直後から水をやれる） | 6.4 |
| もらえる回数 | 拠点ごとに1日1回（日本時間で日付が変わったら、またもらえる） | 6.2 |
| 自分の拠点 | チェックインは水やりか、実っていれば実を1個もらう（タネはもらえず、落ちない）。訪問の記録に残さず、レベルにも数えない | 6.4 |
| 箱庭に置ける数 | 所持数まで。1マスに1個 | 4.4 |
| 箱庭の広さ | 10×10 マス（仮） | — |
| 位置の偽装 | 直前のチェックイン（または拠点の登録）からあり得ない速さで移動していたら断る。dev では確かめない | 12章 |

飾るものは、Lv.1〜3 の種類（各コース3種類 × 5コース）のタネ3つずつの45種類。最初は何も持っておらず、自分でまいたタネを育てて収穫すると集まる（ほかの人の拠点を訪ねてもらえるのはタネだけ。2026-10-28 に変えた）。

> 1人で試すときは、Google アカウントを2つ使い、開発用の位置指定（9章）で別々の地区に拠点を置いて、お互いにチェックインする。

## 6. 地区の判定

### 6.1 流れ

1. **ブラウザ**: 位置情報（緯度・経度）を取る
2. **ブラウザ**: どの市区町村にいるかを調べる（下の 6.2）
3. **ブラウザ**: その市区町村の町丁 geojson（`/geojson/town-district/2020/{prefCode}/{cityCode}.geojson`、CloudFront）を読み、点がどの町丁ポリゴンに入るかを判定して、地区名と地図を出す
4. **Lambda**: 拠点の登録・チェックインのときは、ブラウザから**緯度・経度と市区町村コード**を受け取り、Lambda 側で同じ geojson を読んで判定し直す。ブラウザが言う地区は信用しない。市区町村コードは探す範囲を絞るためだけに使い、点がその市区町村のどの町丁にも入らなければ断る

- 点がポリゴンに入るかの判定は、画面と Lambda で同じ関数を使う（`src/lib/game/chizuTane/` に置き、Lambda からも読む）
- Lambda は geojson を同じコンテナの中のメモリに持っておく
- 町丁を一意に表すキーは、geojson の `KEY_CODE`（e-Stat 小地域のコード）。拠点の主キーにする。地区名は `S_NAME`、代表点は `X_CODE` / `Y_CODE`（戸塚区で確かめたところ、代表点は53地区すべてで自分の地区の中にあった）
- 誤差があるので、判定した地区を見せて「この地区で合っていますか？」と確かめてから登録する（全体設計書 6.1）。境界付近では違う地区になることがあるが、試作ではそのまま受け入れ、どのくらい困るかを確かめる

### 6.2 市区町村を調べる方法（決定）

外部の API（国土地理院の逆ジオコーダなど）には頼らず、うさぽの geojson だけで判定する。ただし都道府県の境界（3.7MB）や市区町村の geojson（北海道は 7MB 超）をチェックインのたびに読むのは重いので、**市区町村ごとの範囲（四隅の緯度・経度）の一覧**を一度だけ作って置いておく。

- 一覧: `public/chizu-tane/municipality-bounds.json`（1892市区町村、88KB）。作り方は `scripts/chizu-tane/build-municipality-bounds.mjs`（市区町村の geojson から作る。47都道府県分を読むのはこのスクリプトを動かすときだけ）
- 画面では、現在地を囲む範囲を持つ市区町村（たいてい1〜3か所）の町丁 geojson だけを順に読んで判定する
- 町丁 geojson の市区町村コードは3桁（例: 横浜市戸塚区は `14/110`）

## 7. データ（Amplify Data のモデル）

既存のゲームと同じく、**モデルはクライアントからは読むだけ、書くのは Lambda だけ**にする（所持数・1日1回・早い者勝ちなどを守るため）。モデル名は `GameTane*`。

| モデル | 主キー | 中身 | クライアント |
|---|---|---|---|
| `GameTanePlayer` | `userId` | 選んだコース、直前のチェックインの地区とその代表点・日時（速さの確認用） | 本人だけ読める |
| `GameTaneBase`（拠点） | `areaKey`（町丁のキー） | 都道府県・市区町村・町丁のコードと名前、拠点の種類、まいたタネ、ランク、まいた日時、地区の代表点（全国農地用）、育ち（たまった水・残っている実の数・いまの実が実った日時・遠くから最後に水をやった日）、落ちているタネの数。市区町村（おでかけの地図）で引けるようにする。**持ち主は持たない**（誰でも読めるので、持ち主の ID からタネの場所をたどれないように） | ログインしていれば誰でも読める |
| `GameTaneOwnership`（持ち主） | `ownerId` + `areaKey` | まいたタネ、まいた日時。自分のタネの一覧・自分のタネかどうかに使う。Lambda は `areaKey` から持ち主を引く | 本人だけ読める |
| `GameTaneShare`（農園を見せる相手） | `ownerId` + `viewerId` | 持ち主が「農園を見せる」にしたフォロワー。はじめは無し | 持ち主が作る・消す。相手も読める |
| `GameTaneVisit`（訪問） | `userId` + `areaKey` | 最初に訪ねた日時、最後にもらった日（日本時間の日付）、訪ねた回数 | 本人だけ読める |
| `GameTaneItem`（所持） | `userId` + `itemId` | 所持数（ガーデンに飾れる数）、初めて手に入れた日時と地区 | 本人だけ読める |
| `GameTaneHarvest`（収穫の記録） | `userId` + `harvestedAt` | 実1個ごとの記録。もの、地区のキーと都道府県・市区町村・町丁の名前、実がなった日時、タネの持ち主（画面では「生産者」）。実をもらうトランザクションの中で足す | 本人だけ読める |
| `GameTaneHeldSeed`（タネ） | `userId` + `itemId` | 持っているタネ（もの単位）の数。まくと減る | 本人だけ読める |
| `GameTaneGarden`（箱庭） | `userId` | 広さ、置いたものの配列（`objects`、`a.json()`） | 本人だけ読める |

- **位置は地区の単位でしか保存しない**。速さの確認にも、チェックインした地区の代表点（ポリゴンの中の1点）を使い、プレイヤーの実際の緯度・経度は保存しない（全体設計書 12章）
- 訪問は、のちにレベル（たずねた拠点の数）を数えるのにもそのまま使える（1拠点1行）
- 拠点の種類とランクは拠点の行に持つ（拠点に置くものは1つだけなので、全体設計書 9章の LocationObjects は分けない）
- 箱庭は1行にまとめる（保存が1回で済み、途中で失敗しても半端な状態が残らない。10×10 なら最大100個で数KB）。重なり順は奥から描けば決まるので持たない
- コースの表（拠点の種類・ランクごとのもの）とアイテムの定義はテーブルにせず、コードの中のマスターデータ（`src/lib/game/chizuTane/` の中）にする。画像を `public/` に置く以上、足すのはどのみちデプロイが要るので、「表に1行足して画像を置く」で済ませる。Lambda も同じ定義を読む。試作の段階から全体設計書 3.3 の「最初に用意する絵」の表（Lv.1〜3 の種類 × タネ3つ × 5コース＝45点）を入れておく

## 8. API（カスタムミューテーション）

どれもログイン必須。ユーザーIDは引数で受け取らず、Cognito の `sub` を使う。

| ミューテーション | 引数 | 処理 |
|---|---|---|
| `startTane` | コース | まだ始めていなければ、コースを決めて、Lv.1 の種類のタネ3つを1個ずつ渡し、空の箱庭を作る |
| `pickUpTaneSeeds` | 緯度・経度・市区町村コード・拾う数 | 地区を判定し直し、速さを確かめ、その地区の拠点に落ちているタネを選んだ数だけ渡す（誰でも早い者勝ち）。「拠点から減らす（その数以上落ちているときだけ）」と「自分のタネに足す」を DynamoDB のトランザクションで行うので、同時に拾っても数がずれず、途中で失敗してもタネが消えない |
| `placeTaneBase` | 緯度・経度・市区町村コード・まくタネ（もの） | 地区を判定し直し、速さを確かめ、そのタネを持っているかを確かめ、その地区に拠点が無ければ、タネのものの種類の拠点をランク1で作ってタネを1つ減らす（同時に置こうとしたときは、DynamoDB の条件付き書き込みで先に書いた方だけが通る） |
| `replantTaneBase` | 地区のキー・まくタネ（もの） | タネ待ちの自分の畑に、同じ種類の畑のタネをまき直す（遠くからでもよい。位置は使わない）。タネ待ちで空き地に戻っていないときだけの条件付きの書き込み。ランクはそのままで、タネから育ち直す。持っているタネが1つ減り、まいたことのあるタネ（レベルの条件）に入る。開拓した地区の数には入らない |
| `checkInTaneBase` | 緯度・経度・市区町村コード | 地区を判定し直し、速さを確かめ、その地区の拠点を探す。1人1つの時間帯に1回。実が残っていれば実を1個渡し（最後の1個ならランクを上げてタネ待ちにする）、無ければ水を10足す（50たまったら実をランク×10個にする）。タネ待ちの畑では何もしない。他の人の拠点に初めて来たときだけ、拠点にタネを1個落とし（直接は渡さない）、訪問を記録する（レベルが上がることがある）。水・実の数は DynamoDB の条件付きの書き込みで変える（同時に来ても数がずれない） |
| `waterTaneBaseRemotely` | 拠点のキー | 自分の拠点にだけ、1日1回、水を1足す（実っている間はできない） |
| `openTaneGarden` | なし | 箱庭と所持しているものを返す |
| `saveTaneGarden` | 配置の配列 | 存在するものか・マスの範囲内か・1マス1個か・所持数を超えていないかを確かめて、本人の箱庭だけを書き換える |

Lambda は3本: `chizu-tane-player`（start / open / save）、`chizu-tane-place`、`chizu-tane-checkin`。Gen2 の Lambda には呼ばれたミューテーションの名前が来ないので、引数の形が同じ place と check-in は分けた。地区の判定と速さの確認は `amplify/functions/shared/chizuTane.ts` にまとめ、geojson を読む2本はメモリとタイムアウトを多めにしている。

## 9. 開発・テスト用の位置指定

位置情報のゲームは、机の前では試せない。開発中と dev 環境では、位置を手で指定できるようにする。

- 「いまいる地区」の画面で、地図をタップした点（緯度・経度）をそのまま現在地として使う。地区の代表点に寄せないので、境界のあたりの判定も実際の位置情報と同じように試せる。となりの市区町村の上をタップすればそちらに移り、遠くへは「緯度,経度」を入力して移る
- 有効にするのは dev 環境（devgame.usapo.net）と手元（localhost）だけ。本番のビルドでは出さない
- dev の Lambda では速さの確認をしない（指定した場所へ一瞬で移れるように）。本番の Lambda では確かめる。ブランチ名で切り替える（`resource.ts` で `AWS_BRANCH` が `main` かを見て環境変数を入れる）
- 位置を手で指定できるのは、ブラウザの位置情報を偽るのと同じこと。本番でもブラウザの開発ツールを使えば偽れるので、これで守りが弱くなるわけではない（全体設計書 12章）

## 10. 画像素材

### 10.1 試作の進め方

- 絵ができるまでは、アイテムごとに持たせた**絵文字**を出す（`courses.ts` の `emoji`）。AI 素材ができたら、そのアイテムに `imageUrl` を足すだけで差し替わる。画像は 48×48 前後で、下端の中央が地面に接する点になるように描く
- 画像生成AIで絵を作る手順とプロンプトは [地図タネ_絵の作り方.md](地図タネ_絵の作り方.md)
- **AI 素材の検討はコードと別に並行して進める**。絵柄を決めて、まず各コースのランク1〜2あたりから8個ほど作り、箱庭のマス目の画像の上に並べて見比べる。気に入った絵柄ができたら、試作の5種類から差し替える

### 10.2 絵柄の方向

- かわいらしいミニチュア風、またはローポリ風（試して決める）
- 柔らかな色合い、斜め上から見た視点、シンプルで見分けやすい形
- 背景を透過した PNG。ファイル名はアイテムID

### 10.3 素材ごとの確認

- 背景が透過されているか、輪郭がはっきりしているか
- 縮小しても見分けられるか（箱庭の1マスはスマホで 30px 前後、集めたものの一覧ではもう少し大きい）
- 視点と影の向きが他の素材とそろっているか
- 縦横比や余白が極端に違わないか
- 必要なら切り抜き・大きさの調整をする

## 11. 評価の観点

試作ができたら、dev 環境で実際に歩いて次を確かめる。結果を見て、全体設計書のフェーズ4以降（成長・ランクアップ・レベル）に進むかを決める。

1. 拠点を置く → 別の地区でチェックインする、の流れが説明なしで分かるか
2. 「他の人のタネに行ってみたい」と思えるか。もらえたときにうれしいか
3. 地区の判定は実用になるか（誤差で違う地区になる頻度、境界付近、建物の中）
4. 集めたものの一覧・ガーデンが、ご褒美として効いているか。違うコースのものを混ぜても違和感がないか
5. スマホで操作しやすいか（位置情報の許可、地図、マス目の大きさ）
6. 費用と運用の手間が増えすぎないか（Lambda での geojson の読み込み、DynamoDB）
